1. TENANT & MULTI-COMPANY HIERARCHY FLOW:
   Tenant (tenant_masters)
     ├── TenantMembership (tenant_memberships) -> User (app_users)
     ├── TenantSubscription (tenant_subscriptions) -> SubscriptionPlan (subscription_plans)
     ├── TenantModuleEntitlement (tenant_module_entitlements) [Module entitlements matrix]
     └── Company (companies) [Scoped by tenant_id]
           ├── CompanyMembership (company_memberships) -> User
           ├── StoreLocation (store_locations) [Physical outlets / Kiosks]
           └── CompanyPostingConfig (company_posting_configs) [Chart of Accounts default mappings]

2. COMMERCIAL TRADE & AP/AR BILL ALLOCATION FLOW:
   Counterparty (counterparty_parties) [Customers, Vendors, Creditors, Debtors]
     ├── CommercialDocument (commercial_documents) [SALES_INVOICE, PURCHASE_INVOICE, CREDIT/DEBIT NOTE]
     │     ├── lines [CommercialDocumentLineSchema: StockItem, Godown, UOM, GST Tax rates]
     │     └── StockMovement (stock_movements) [Triggered inventory movement on post]
     ├── BillAllocation (bill_allocations) [Links payment document to unpaid invoice document]
     └── Journal (journals) + JournalEntry (journal_entries) [Automated double-entry posting]

3. RESTAURANT POS, KIOSK & INGREDIENT DEDUCTION FLOW:
   StoreLocation (store_locations) + RestaurantTable (restaurant_tables)
     └── RestaurantOrder (restaurant_orders)
           ├── items [StockItem, ModifierGroup options, excluded ingredients]
           ├── payment_details [UPI Dynamic QR, EDC Card, Cash, Provider Ref]
           ├── RecipeBOM (recipe_boms) [Recipe specification per finished menu item]
           │     └── ingredients [Raw material StockItem consumption]
           ├── StockMovement (stock_movements) [RECIPE_CONSUMPTION automated entries]
           └── CommercialDocument (commercial_documents) [Commercial invoice mirror]

4. GENERAL LEDGER DOUBLE-ENTRY CLOSING FLOW:
   Journal (journals)
     ├── JournalEntry (journal_entries) -> LedgerAccount (ledger_accounts)
     ├── FiscalPeriod (fiscal_periods) [OPEN, SOFT_CLOSED, HARD_CLOSED, LOCKED]
     ├── TrialBalanceSnapshot (trial_balance_snapshots)
     │     └── TrialBalanceLine (trial_balance_lines)
     ├── SubledgerBalance (subledger_balances) [AR, AP, Fiduciary, Operating Cash vs GL]
     └── GLExportBatch (gl_export_batches) [External ERP export payload - SAP/NetSuite]

5. FIDUCIARY TRUST & INSURANCE SETTLEMENT FLOW:
   FiduciaryAccount (fiduciary_accounts) [Segregated Texas § 4053 statutory trust]
     ├── BordereauDefinition (bordereau_definitions)
     ├── BordereauRun (bordereau_runs)
     │     └── BordereauLine (bordereau_lines) [Policy coverage, premium, MGA withholding]
     └── SettlementStatement (settlement_statements)
           ├── SettlementLine (settlement_lines) [Gross eligible premium vs claims offset]
           └── Journal (journals) [Trust disbursement posting]

6. EVENT SOURCING & POSTING RULES ENGINE FLOW:
   OutboxEvent (outbox_events) / EventDefinition (event_definitions)
     ├── PostingRule (posting_rules) [Evaluates business conditions against event payload]
     │     ├── PostingRuleLine (posting_rule_lines) [Calculates debits/credits via AST formula]
     │     └── PostingRuleTestCase (posting_rule_test_cases) [Regression test suite]
     └── Journal (journals) [Direct automated GL creation]

// === UNRESOLVED / AMBIGUOUS REFERENCES ===
// Analysis of polymorphic, string-based, or external identifiers
// =============================================================================

1. StockMovement.source_document_id:
   - Stored as String (not ObjectId ref).
   - Inferred targets: CommercialDocument._id, OpeningStock, or JobWorkOrder._id depending on source_document_type.
   - Preserves polymorphic loosely coupled integration.

2. Invoice.policy_id & InstallmentSchedule.policy_id:
   - Stored as String (e.g. "POL-TX-8821").
   - Represents external insurance core system policy identifier; no internal Policy collection exists in this ERP database.

3. SettlementStatement.carrier_party_id & BordereauDefinition.carrier_party_id:
   - Stored as String codes (e.g. "CARRIER-SUMMIT") referencing Party.party_code rather than ObjectId _id.

4. Journal.reference_id:
   - Stored as String with polymorphic reference_type enum ('NONE', 'REFERENCE_ONLY', 'INVOICE_ADJUSTMENT', 'SETTLEMENT').

1. Foreign Key Enforcement:
   - In DBML, 'Ref:' represents relational foreign keys. In MongoDB, these are logical application-level
     references (Schema.Types.ObjectId with 'ref'). MongoDB does not enforce referential integrity or cascading
     deletes natively; integrity is enforced by Mongoose middleware, controllers, and service transactions.

2. Embedded Subdocuments vs Tables:
   - DBML tables in this deliverable represent independent MongoDB collections. Nested documents (such as
     CommercialDocument.lines or RestaurantOrder.items) are documented as jsonb / embedded subdocuments
     inside the parent collection to preserve exact document-oriented storage reality.

3. Dynamic Schemas and Mixed Types:
   - Fields typed as Schema.Types.Mixed (e.g., metadata, dimensions, role_details) allow flexible arbitrary JSON
     structures in MongoDB documents. In DBML, these are typed as jsonb.
